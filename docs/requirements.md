# 要件定義：請求書AI処理SaaS

## 目的

請求書のPDF・画像をアップロードすると、AIが取引先・金額・税額・登録番号などを抽出し、インボイス制度の要件と計算の整合性を自動で検証したうえで、担当者の確認と承認を経て仕訳CSVに出力する。示すのは「そのまま納品できる業務システムを作れる」こと。

- 業務システムとしての完成度：ログイン、組織と役割による権限、承認フロー、監査ログ、課金
- AIを業務に組み込む設計：AIの出力を信用せず、確信度と検証ルールで人の確認箇所を絞る
- 日本の実務への理解：適格請求書の記載事項、税率ごとの消費税、源泉徴収の検証
- 測定できる品質：正解付きの合成請求書で項目別の抽出精度を測る

## 役割

| 役割   | 主な作業                                       |
| ------ | ---------------------------------------------- |
| 担当者 | アップロード、AI抽出結果の確認・修正、承認依頼 |
| 承認者 | 承認・差し戻し（自分の提出分は不可）           |
| 管理者 | CSV出力、メンバーとプラン、監査ログ            |

## 機能要件

| ID   | 機能                                                 | 優先度 | 状態                                   |
| ---- | ---------------------------------------------------- | ------ | -------------------------------------- |
| F-01 | ログインと組織                                       | MVP    | 実装                                   |
| F-02 | 役割と権限（APIとDBで強制）                          | MVP    | 実装                                   |
| F-03 | アップロード（形式・サイズ・ページ数の検査）         | MVP    | 実装                                   |
| F-04 | AI抽出（構造化・確信度・2回の読み比べ）              | MVP    | 実装（Claude / Codex / デモ用データ）  |
| F-05 | 自動検証（登録番号・税額・合計・源泉・日付・重複）   | MVP    | 実装                                   |
| F-06 | 確認・修正画面（原本と並列、要確認の強調、修正履歴） | MVP    | 実装                                   |
| F-07 | 承認フロー（差し戻し理由必須、自己承認禁止）         | MVP    | 実装                                   |
| F-08 | 勘定科目の推定                                       | MVP    | 実装（取引先マスタ→明細の語→AIの推定） |
| F-09 | 仕訳CSV出力（二重出力の防止）                        | MVP    | 実装                                   |
| F-10 | 監査ログ（改ざん不可）                               | MVP    | 実装                                   |
| F-11 | 課金（プラン上限、Stripe Webhook）                   | MVP    | 実装（キー未設定時は無効）             |
| F-13 | 取引先マスタ                                         | 追加   | 承認時に科目を記憶する範囲で実装       |

次の段階の候補：一括アップロード（F-12）、国税庁の公表サイトAPIによる登録番号の照会（F-14）。どちらも `uploadInvoice()` と検証ルールの入口に足せる形にしてある。

## 検証ルール

| コード                | 内容                                                                  | 重さ   |
| --------------------- | --------------------------------------------------------------------- | ------ |
| REG_FORMAT            | 「T」+数字13桁                                                        | エラー |
| REG_CHECK_DIGIT       | 法人番号の検査数字（発行者名が法人のときだけ）                        | 警告   |
| QUALIFIED_ITEMS       | 適格請求書の記載事項の不足                                            | 警告   |
| TAX_CALC              | 税率ごとの税額が端数処理の範囲内か                                    | エラー |
| TOTAL_MISMATCH        | 税率別の合計−源泉徴収＝請求額                                         | エラー |
| LINES_MISMATCH        | 明細の合計と税率別の金額                                              | 警告   |
| WITHHOLDING           | 10.21%（100万円超の部分は20.42%）                                     | 警告   |
| DUE_BEFORE_ISSUE ほか | 日付の妥当性                                                          | 警告   |
| DUPLICATE             | 同じ登録番号・請求書番号・金額                                        | エラー |
| NOT_IN_SOURCE         | PDFの文字情報に値が見つからない                                       | 警告   |
| AI_UNCERTAIN          | AIが自信がないと申告した項目、2回の読み取りで割れた項目（保存で解除） | 警告   |

エラーがあると承認依頼できない。警告は理由を入力すれば進める。

## 非機能要件

| 要件                                       | 目標                             | 状態                                                |
| ------------------------------------------ | -------------------------------- | --------------------------------------------------- |
| 組織をまたいだ参照                         | 0件（RLS）                       | テストで確認                                        |
| 役割を超えた操作・自己承認・出力済みの編集 | DBで拒否                         | テストで確認                                        |
| アップロード                               | 先頭バイトで判定、10MB・20ページ | 実装                                                |
| Stripe Webhook                             | 署名検証と冪等                   | テストで確認                                        |
| 必須項目の抽出精度                         | 95%以上                          | 架空40枚で100%（ChatGPT / Codex、2026-10-20）       |
| 誤りを仕込んだ請求書の見逃し               | 0件                              | 正解データでもAI経由（ChatGPT / Codex）でも 0 / 6枚 |
| 誤検出（正しい請求書を誤りと判定）         | 0件                              | 正解データでもAI経由でも 0 / 34枚                   |
| 読み違いの見逃し                           | 0件                              | AI経由で 0 / 40枚（2回の読み比べ）                  |
| 1枚あたりの抽出時間                        | 中央値15秒以内                   | 中央値9.7秒（ChatGPT / Codex、画像、2回を並列）     |
| 画面の大きさ                               | 280px幅〜4K、横向きスマホ        | 25種でテスト（はみ出し・欠け・重なり0件）           |
| アクセシビリティ                           | WCAG 2.1 A/AA                    | 全画面でaxeの違反0件（Chromium・WebKit）            |
| 監査ログ                                   | 改ざん不可                       | 権限で確認                                          |

## 範囲

受け取った請求書の読み取りから仕訳CSVの出力まで。会計ソフトへのAPI連携、支払い、請求書の発行、電子帳簿保存法に沿った保存、外貨・多言語、SSOは、導入先の仕組みと組み合わせる。
