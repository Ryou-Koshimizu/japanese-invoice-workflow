### 2回読み比べる方式にした理由（同じ日の1回読みの測定）

1回だけ読む方式で同じ40枚を2回測り、次の3件を観測しました。同じ請求書を単独で3回ずつ読み直すと、inv-20・inv-24は3回とも正しく、inv-11は3回中2回正しく読めました。たまに起きる取りこぼしです。

| 測定                                                                    | 観測                                                                                                                                                     |
| ----------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [1回目](evidence/eval-codex-2026-10-20-single-read-a.json)（`f18f353`） | inv-20 の登録番号の桁数を読み違えた（検証ルールの「形式」エラーで捕捉）。inv-24 は応答が115秒の上限を超えた                                              |
| [2回目](evidence/eval-codex-2026-10-20-single-read-b.json)（`c1e58c1`） | inv-11 の発行者名「株式会社ナギサ不動産管理」を「株式会社サギサ不動産管理」と1文字読み違えた。名称は計算で確かめられないため、検証ルールでは捕捉できない |

1文字の読み違いは、ルールでは見つけられない種類の誤りです。そこで「2回独立に読み、食い違えば3回目の多数決、それでも割れたら人に確認を回す」方式に変え、上の測定で40/40・誤検出0件・すり抜け0件を確認しました。応答のない呼び出しは同じ読み取りの中で3回目に置き換わります。AIの呼び出しは1回の読み取りで2〜3回、1枚につき9回までで、上限はDBのCHECK制約で強制します。

### 正しい請求書への誤検出をなくした変更

測定の前に、検証ルールを正解データ40枚に当てたところ、源泉徴収の6枚（発行者は個人事業者）で「法人番号の検査数字と一致しない」警告が出ていました。個人事業者の登録番号は法人番号ではないため、検査数字の確認は発行者名が法人（株式会社・合同会社など）のときだけに絞りました。正解データ40枚で、出る警告・エラーが仕込んだ誤りと完全に一致することをテストで固定しています（`tests/rules.test.ts`）。
