# 脅威と対策

| 脅威                                           | 対策                                                                                                                                           | 確認方法                                                              |
| ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 他組織のデータ参照・書き込み                   | 全リクエストを `app_user` ロールで実行し、RLSで `org_id` を強制。組織IDを偽装しても書き込めない                                                | `tests/database.test.ts`、`tests/postgres.test.ts`（実PostgreSQL 16） |
| 役割を超えた操作・自己承認                     | アプリの `can()` に加え、DBトリガーが遷移・役割・提出者を検査                                                                                  | 承認者が自分の依頼をSQLで直接承認しようとしても拒否されるテスト       |
| 出力済み請求書の改変（二重計上・改ざん）       | 出力済みは更新不可（トリガー）。DELETE権限なし                                                                                                 | テスト                                                                |
| 監査ログの改ざん                               | トリガーのみが書き込み、`app_user` にUPDATE・DELETE権限なし                                                                                    | テスト                                                                |
| パスワード・セッションの漏えい                 | scryptでハッシュ化。`app_user` は `password_hash` 列と `sessions` 表を読めない（SECURITY DEFINER関数のみ）。セッショントークンはハッシュで保存 | テスト（開発中にこの権限の漏れを発見して修正）                        |
| パスワード総当たり                             | 同じメールと接続元で5回失敗すると5分停止。未登録メールでも同じ時間がかかるようにダミーのハッシュ計算を行う                                     | 実装（プロセス内メモリのため複数台では共有されない）                  |
| CSRF                                           | SameSite=Lax cookie、状態を変えるAPIでOriginを検査                                                                                             | E2E（別Originからの出力要求が403）                                    |
| 不正なファイル                                 | 拡張子やContent-Typeではなく先頭バイトで判定。10MB・20ページまで。PDFの読み込み失敗は拒否                                                      | 実装                                                                  |
| CSVによる数式実行                              | `=` `+` `-` `@` で始まる文字列セルの先頭に `'` を付ける                                                                                        | `tests/core.test.ts`                                                  |
| AIによる値の捏造                               | AIは抽出のみ。検証は決定的なルール。PDFの文字情報に値が存在するかを照合                                                                        | `tests/core.test.ts`                                                  |
| 請求書内の文章によるプロンプトインジェクション | 文書はデータとして扱うよう指示。AIは抽出結果を返すだけで、ツール実行やDB操作の権限を持たない                                                   | 構造上の制約（Codexはツール無効の読み取り専用サンドボックス）         |
| Stripeの偽通知・再送                           | 生のリクエスト本文で署名を検証。イベントIDで一度だけ処理                                                                                       | `tests/billing.test.ts`                                               |
| 超過利用                                       | 月の処理枚数をDBのトリガーで強制                                                                                                               | テスト                                                                |
| RLSを迂回できる接続                            | 実運用モードの起動時に、接続ロールがスーパーユーザーやBYPASSRLSでないこと、`app_user` のメンバーであることを検査                               | 実装                                                                  |

## 対象外

- SSO、パスワードリセット、多要素認証
- 複数台構成でのログイン試行制限の共有
- ウイルススキャン
- 電子帳簿保存法の要件（タイムスタンプ等）
