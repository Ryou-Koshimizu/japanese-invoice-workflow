# ADR 003：AIを呼ばない公開デモ

## 判断

公開デモ（`APP_MODE=demo`）はプロセス内のPGlite（WASM版PostgreSQL）に同じスキーマを適用し、架空の会社・3役割・7枚の請求書を、UIと同じサービス関数を通して投入する。AI抽出は `fixtures/demo-extractions.json` の事前データを返す。

事前データは評価用の正解データから機械的に作る。読み取りにくい画像のうちinv-29だけは、登録番号の末尾2桁を入れ替えたうえで「登録番号に自信がない」という申告を付け、確認画面が疑わしい値を捉える様子を見せる。ほかの39枚は正解どおりで、正しい請求書に警告は出ない。画面には「デモ用の事前データ（正解データから作成。AIの出力とは別）」と表示し、精度の説明には使わない。

## 理由

- 作者のAPIキーで誰でも使える公開サービスは、費用と乱用のリスクがある。
- 固定の画面だけでは権限・承認・監査の動きが伝わらない。デモも本番と同じSQLとRLSを通す。

## 公開デモをホストに置く場合

Vercelでは画面とAPIが別々の関数・別々のインスタンスで動くため、プロセス内のPGliteでは「ログインした直後の画面でログインが外れる」状態になった（実測：同じセッションで20回中2回）。次の2点で解決した。

- **共有のデモ用DB**：`DEMO_DATABASE_URL` を設定すると、PGliteの代わりにデモ専用のPostgreSQL（Neonの無料枠）を使う（`src/server/demo-postgres.ts`）。スキーマの作成と架空データの投入はアドバイザリーロックの下で1台だけが行い、1日たつか管理者が「デモを初期化」を押すと元のデータに戻す。リクエストは本番と同じく `app_user` ロールとRLSを通す。
- **1つの関数で動かす**：`scripts/vercel-build.mjs` がNext.jsのstandalone出力をBuild Output APIの関数1つにまとめる。

## 制約

- 共有DBを使わない場合、デモのデータはサーバーの再起動で初期化される。
- 共有DBは接続ロールがテーブルの所有者になる（作成と初期化を行うため）。デモ専用のDBに限り、実運用モードの「所有者では接続しない」検査は適用しない。
- 公開デモでアップロードできるのは同梱のサンプル（ファイルのSHA-256で照合）だけ。
