# ADR 005：AIに2回読ませて読み比べる

## 判断

1枚の請求書を、AIに2回独立に（並列で）読ませる。全項目が一致すればその値を使う。食い違った項目があれば3回目を読ませ、項目ごとに多数決で決める。3回とも割れた項目は1回目の値のまま「AIの読み取りが一致しなかった」警告（`AI_UNCERTAIN`）を付け、人が原本で確かめる。実装は `src/adapters/reliable.ts` で、アプリと精度評価（`npm run eval`）の両方が同じものを通る。

- 応答のない呼び出し（タイムアウト・空の応答）は、同じ読み取りの3回目で置き換える。再試行するのは決まったエラーコードだけで、利用上限・認証・形式の拒否は再試行しない。
- AIの呼び出しは1回の読み取りで2〜3回。2回目以降の呼び出しの前にDBで回数を数え、1枚につき9回（読み取り3回分）までをCHECK制約で強制する。

## 理由

1回読みの測定（[検証記録](../verification.md)）で、発行者名の1文字の読み違い（ナ→サ）を観測した。名称・請求書番号・日付の読み違いは計算で確かめられないため、[検証ルール](004-validation-independent-of-ai.md)では見つからない。独立した2回の読み取りが同じ誤りをする確率は、1回の誤りの確率よりずっと小さい。

## 代償

- AIの利用量（トークン）は約2倍。時間は2回を並列に読むため大きくは変わらない（同じ日の1回読みの中央値8.7〜9.7秒に対し、9.7秒）。
- 2回とも同じ誤りをした場合は見つからない。その確率を下げたいときは、読み取りの回数を増やすか、別のモデルと読み比べる（差し替え境界は `ExtractionProvider`）。
