# Engineering rules

- Business rules live in two places on purpose: `src/core` (pure, for messages and UI) and `db/schema.sql` (triggers and row-level security, the authority). Change both together and add a database test.
- Every request runs through `asUser()` as the restricted `app_user` role. Never query as the connection owner from request code.
- The AI only extracts. Validation (`src/core/rules.ts`) never calls a model. Do not let model output skip `extractionSchema`.
- The public demo uses `fixtures/demo-extractions.json`, built from the eval truth. Label it as demo data; never count it as AI accuracy.
- Eval invoices are fictional and generated by `scripts/generate-invoices.ts`. Regenerate fixtures after changing them.
- No secrets, real company data or real registration numbers in the repository.
- Keep commits focused by feature. Record design trade-offs in `docs/adr`.
